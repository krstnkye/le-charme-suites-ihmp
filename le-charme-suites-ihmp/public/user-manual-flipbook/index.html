Chapter 01Getting started

Quick Start

Start the local server, open the portal and sign in with an approved staff account.

Start the application.
On the host computer, run setup-and-run.bat for first-time setup. For shared private-LAN use, run run-shared-lan-server.bat.

Open the portal.
Use http://127.0.0.1:8000 on the host or the address displayed by the LAN launcher on another authorized device.

Choose your department.
Select Administrator, Receptionist, Billing or Housekeeping, then enter your approved work email and password.

Confirm the workspace.
The sidebar and dashboard should match your assigned role.

Never place the real .env file, passwords, API keys or guest database on a public repository.
Host computer and local network must remain available during shared operation.Page 3
Chapter 02Access control

Accounts and Sign In

Each person uses an individual account. The selected department must match the role assigned by an administrator.

A

Administrator

Approves accounts, manages permissions and rooms, reviews audit history, operates the Integration Center and views reports.

F

Front Desk

Manages guests, reservations, confirmations, room assignments, arrivals, check-ins and front-desk records.

B

Billing

Reviews guest folios, records charges and payments, completes check-out and prints bills or receipts.

H

Housekeeping

Receives turnover tasks, updates cleaning status, records inspection and releases rooms when work is complete.

Newly registered staff must wait for administrator approval. Administrators use the separate /admin sign-in page.
Use Forgot password? when an account cannot sign in.Page 4
Chapter 03Guest and reservation operations

Front Desk Workflow

The front desk turns a booking request into a confirmed stay while keeping guest, room and reservation records connected.

Guest record→Reservation→Confirmation→Room assignment→Check-in

Create a reservation

  1. Open Reservations and select New Reservation.
  2. Choose or create the guest.
  3. Select dates, guests and an available room.
  4. Review the agreed rate and save.

Confirm an online request

  1. Open the online request from the alert or reservation list.
  2. Verify availability and guest details.
  3. Confirm the request.
  4. Print the registration card when needed.
Only fictional demonstration data should be used unless the institution and hotel have approved real-data processing.
Availability checks prevent overlapping bookings.Page 5
Chapter 04Arrival procedure

Check In

Check-in moves a confirmed reservation into an active stay and marks the assigned room occupied.

Open the arrival queue.
Select Check-ins and locate the confirmed reservation.

Verify the guest and stay.
Check the guest, dates, room, party size and agreed rate.

Confirm room readiness.
Do not check a guest into a room still marked cleaning or maintenance.

Complete check-in.
Submit the record and confirm that the room becomes occupied.

If the selected room is not ready, assign another available room or wait for Housekeeping to complete the release procedure.
The system records the operational event in shared history.Page 6
Chapter 05Folio and payment

Billing and Check Out

The server calculates the guest folio from the agreed room rate, extra-guest charges and recorded transactions.

Before settlement

  • Choose the active guest bill.
  • Review room and extra charges.
  • Add authorized transaction charges.
  • Open the printable bill for review.

Complete settlement

  • Enter the amount paid or use Pay in full.
  • Select Paid, Partial or Unpaid correctly.
  • Submit Settle Guest Bill / Check-out.
  • Print the saved receipt.
Active stay→Guest folio→Payment→Receipt snapshot→Turnover task
A remaining balance can be recorded later from the completed check-out record. Refund and void rules require the hotel’s approved policy.
Receipts use saved check-out amounts instead of recalculating current room rates.Page 7
Chapter 06Room readiness

Housekeeping

Check-out creates a turnover task. Housekeeping follows the approved task sequence before the room becomes available again.

Queued→In progress→Inspection→Completed→Room available

Daily procedure

  1. Open Housekeeping Tasks.
  2. Choose the assigned room task.
  3. Update the status in order.
  4. Add useful operational notes.
  5. Complete the required inspection.

Exceptions

  • Record maintenance defects instead of releasing the room.
  • Do not skip required status transitions.
  • Stayover and simple requests may use their permitted direct completion path.
  • Ask an administrator when access is incorrect.
The final cleaning task controls room release.Page 8
Chapter 07Department coordination

Messages and Shared History

Department Messages provides persistent internal notices while the shared database keeps authorized workspaces synchronized.

Send a message

  1. Open Messages.
  2. Choose a department or All Departments.
  3. Set the priority.
  4. Write a clear subject and message.
  5. Send and verify it in history.

Read history

  • Opening a message records acknowledgement.
  • Sender, recipient, priority and time remain visible.
  • Audit Logs record important account and operational events.
  • Authorized reports summarize shared records.
For the defense, send a Front Desk message to Housekeeping, acknowledge it from Housekeeping and show the saved read history.
Messages are stored locally in the shared database.Page 9
Chapter 08System control

Administration

Administrators maintain accounts, permissions, rooms, operational settings and traceable system history.

Accounts and permissions

  • Approve or reject new staff accounts.
  • Assign the correct role.
  • Use the permission matrix for capabilities.
  • Revoke access promptly when responsibilities change.

Rooms and records

  • Add or edit room master data.
  • Use maintenance status when a room is unavailable.
  • Review guest and operational records.
  • Use Audit Logs to trace account activity.

Integration Center

Check database and runtime health, API state, transfer history, exports and the embedded system guide.

Reports

Review operational and transaction reports without granting unnecessary edit access.

Administrative actions must use an approved individual account.Page 10
Chapter 09Integration operations

API and File Transfer

The Integration Center supports controlled CSV/JSON exports and protected API access for approved demonstrations.

Export a dataset

  1. Open Admin → Integration Center.
  2. Select Guests, Rooms, Reservations or Transactions.
  3. Choose CSV or JSON.
  4. Download and verify the transfer-history row.

API access

  • Use a scoped key or JWT as required.
  • Keep credentials outside source control.
  • Use the versioned /api/v1 endpoints.
  • Review the recorded checksum and result.
The official hotel website and production systems are not connected. The website booking flow is an academic simulation unless written authorization and credentials are provided.
Exports exclude passwords and protected credentials.Page 11
Chapter 10Responsible operation

Security and Privacy

Use the minimum access needed, protect credentials and keep demonstration data fictional.

Account safety

  • Use a unique password for every account.
  • Never share administrator credentials.
  • Sign out from shared computers.
  • Report repeated failed sign-ins.

Data safety

  • Do not enter real guest data without approval.
  • Keep .env and database files private.
  • Use approved offline backups.
  • Do not publish API keys or exported records.
The application is an academic prototype. A real deployment requires hotel validation, privacy review, HTTPS, managed backups, monitoring and independent security testing.
Follow the Data Privacy Act of 2012 and institutional policy.Page 12
Chapter 11Common problems

Troubleshooting

Cannot sign in

Choose the correct department, confirm administrator approval, check the work email and use Forgot password? if needed.

Page or menu is missing

Role-based navigation hides unauthorized modules. Sign in with the correct approved role or ask an administrator to review permissions.

Server will not start

Confirm PHP and Composer are installed, verify port 8000 is free, then run php artisan optimize:clear.

Database or table error

Stop the server, confirm the SQLite file exists, then run php artisan migrate --seed.

Another laptop cannot connect

Use the host IPv4 address, remain on the same private network and allow PHP through the Windows firewall for private networks.

Integration API returns 503

The API is intentionally disabled until its scoped credential is configured on the host.

Detailed setup instructions are in GROUPMATES_SETUP.md.Page 13
Chapter 12End of session

Sign Out and Shutdown

Close each work session safely and stop the host only after active users have finished.

Finish pending records.
Confirm that reservations, payments, room tasks and messages were saved.

Sign out.
Use Logout at the bottom of the sidebar. Do not simply close a shared browser window.

Confirm other users have finished.
Stopping the host disconnects every department device.

Stop the server.
Press Ctrl + C in the host terminal and confirm when prompted.

Back up approved data.
Create an offline backup only through the approved procedure and store it securely.

Never leave a shared workstation signed in.Page 14
